Bookmatch

Book discovery beyond a title search: preferences, readable matches and a place to save the next read.

View live project ↗GitHub / source ↗
01 / Starting point

A reader knows more than a book title.

Sometimes the request is a title or an author. Sometimes it is a combination of subjects, settings or tropes. Bookmatch explores how to turn that intent into browsable results with enough context to decide what to read next.

Keep discovery close to the search.

The interface supports title, author and subject searches, with a separate preference-led discovery flow. Results can be inspected in Details and saved to a local reading list, keeping the path from browsing to a next read short.

Make the result useful before the click out.

Book metadata and a reading/source link let readers assess a result without starting over elsewhere. Missing covers and incomplete metadata are expected API conditions, so the implementation includes fallbacks instead of assuming a perfect catalogue.

02 / My contribution

The product experience and the implementation behind it.

Designed and built the Flask application and JavaScript interface, connecting book-catalog data to search, subject/trope discovery, recommendation ranking, book details and a persistent reading list. The work includes the product flow, API handling, metadata normalization and the logic used to assess a match.

03 / Recommendation decisions

Retrieval is not proof of a match.

01

Retrieve candidates

Bounded query variants cover related vocabulary. Sports queries expand into concrete sports.

02

Combine metadata

Merge by ISBN or matching title and author; preserve richer descriptions, covers and reading links.

03

Check the evidence

Descriptions and targeted relevance inform concept matches. Fuzzy query membership alone does not prove an M/M or F/F pairing.

04

Rank & explain

Full matches rank ahead of partial ones. Evidence and missing-concept fields describe the result’s fit.

04 / Technical choices

Build for imperfect external data.

The implementation separates catalog retrieval from normalization and ranking. Cached requests reduce repeated work; metadata and cover fallbacks account for incomplete records. Query and page validation, readable API errors and regression tests cover the less visible parts of the experience: duplicate records, exact-title relevance, false-positive pairings, pagination and bounded retrieval.

05 / What this work demonstrates

A result the reader can understand and keep.

The finished interface connects discovery, browsing, details and saving in one flow. Author and year filters narrow the results; pagination keeps larger result sets manageable; a browser-persisted reading list makes it easy to return to a book. Match explanations make the recommendation logic inspectable, including where catalogue evidence is incomplete.
