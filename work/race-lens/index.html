Race Lens

An interactive F1 race replay designed around the questions new viewers actually ask.

The project began with a usability question: how do timing, tyres and a track map become understandable without knowing F1 shorthand first?

The problem was not missing information. It was knowing what the information meant.

F1 broadcasts already show timing, tyres, positions, maps and race-control signals. The audit asked a narrower question: where does the interface assume knowledge a newer viewer may not have?

Timing

“+1.827” from what?

Gap to the leader and interval to the car ahead can look almost identical if the reference is not labeled.

Tyres

Colour is shorthand.

Knowing that yellow means medium still does not tell a novice why tyre age matters or when a stop changes the race.

Track map

Close dots are not always a battle.

Pit cycles, lapped cars and different race positions can make spatial proximity misleading on its own.

Race state

Flags change the meaning of everything.

Safety cars, blue flags and penalties need context; an icon alone can leave the viewer guessing what happens next.

Make the reference explicit.

The redesign labels the gap as seconds behind the leader instead of relying on a viewer to infer the reference. Driver names sit beside the three-letter codes so the timing view does not require memorizing the grid first.

Use the map for orientation, then add race meaning.

The map stays useful for seeing where cars are, but Race Lens pairs it with running order and a selected-driver panel. Position, timing and tyre context explain why two nearby cars may—or may not—be fighting each other.

Translate tyre shorthand into a decision a viewer can follow.

The driver panel combines the compound name, colour, age in laps and pit status. The point is not to teach tyre strategy in a paragraph; it is to put the information beside the moment when it matters.

I turned “this is confusing” into things a novice could actually be asked to do.

01Read the timing tower and explain a gap versus the leader.
02Interpret the telemetry/sector colours without being told the answer first.
03Use tyre compound and tyre age to describe what might matter next.
04Look at the track map and identify which cars appear to be in a battle.
05Reason through a pit stop or safety-car moment when the order changes quickly.
06Explain blue flags or penalties from the information visible on screen.

The protocol was the bridge between critique and design.

Instead of asking “do you understand F1?”, the tasks isolate specific pieces of the broadcast language. That gave the redesign concrete targets: label the reference, pair colour with text, narrate recent changes and let detail appear when the viewer asks for it.

Layout correction

The wall pushed the track down and made the main visual harder to read, so the driver controls and running order moved beside the track instead.

Comparison should remove mental arithmetic, not add another dashboard.

Two driver selectors put timing, tyre compound, tyre age and pit state side by side, then summarize the gap in a sentence. The data and track geometry are illustrative; the prototype is testing the interaction model, not reproducing a real Grand Prix.

HTML, CSS and JavaScript keep the replay state synchronized.

Changing the lap updates the SVG track, driver markers, running order, tyre state and comparison copy together. The result is a working interaction prototype that lets the research question be experienced instead of only described.
